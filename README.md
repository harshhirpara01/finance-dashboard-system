# Finance Dashboard System (Backend)

Backend for a finance dashboard: **FastAPI**, **SQLAlchemy**, **SQLite** (`finance.db`), and **JWT** auth. Interactive API docs are generated by FastAPI (**Swagger UI** and **ReDoc**).

## Tech stack

| Area | Choice |
|------|--------|
| Framework | FastAPI |
| ORM | SQLAlchemy 2.x |
| DB | SQLite (`./finance.db`) |
| Auth | JWT (`Authorization: Bearer <token>`) |
| Validation | Pydantic v2 |

## Features (high level)

- **Users:** CRUD-style operations, soft delete, active/inactive status, block/unblock (admin).
- **Auth:** Login returns a bearer token; protected routes use `HTTPBearer`.
- **Financial records:** Create, list, filter (type, category, date range), update, soft delete.
- **Dashboard:** Summary totals, category breakdown, recent activity, monthly/weekly trends.
- **Uniform JSON responses:** Business logic uses two shared helpers so success and error bodies follow the same shape across APIs (see below).

## Standard API responses (advanced)

Handlers intentionally avoid ad-hoc JSON. They call **`successResponse`** and **`errorResponse`** from [`common/responses.py`](common/responses.py), so clients always get a predictable envelope:

| Field | Success | Error |
|--------|---------|--------|
| `status` | `"success"` | `"error"` |
| `message` | Human-readable message | Human-readable message |
| `data` | Payload (object, list, etc.) | Optional extra context (often `{}`) |

Example success:

```json
{
  "status": "success",
  "message": "Login successful",
  "data": { "access_token": "...", "token_type": "bearer", "user": { } }
}
```

Example error (from your helpers):

```json
{
  "status": "error",
  "message": "Access denied: Admins only",
  "data": {}
}
```

This keeps **frontend and API tests simple**: check `status`, read `message`, use `data` for the real content.  
**Note:** FastAPI itself may still return its default JSON for some **dependency-level** failures (for example invalid or expired JWT on `HTTPBearer`), which is not wrapped by `errorResponse`. Everything that returns `successResponse` / `errorResponse` follows the table above.

## Local setup

### 1. Clone and enter the project

```bash
cd finance-dashboard-system
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

### 3. Activate the virtual environment

**Windows — PowerShell**

```powershell
.\venv\Scripts\Activate.ps1
```

If execution policy blocks this, run once (current user):

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

**Windows — Command Prompt**

```cmd
venv\Scripts\activate.bat
```

**Linux / macOS**

```bash
source venv/bin/activate
```

Your prompt should show `(venv)` when it is active.

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

### 5. Environment variables

Copy the example env file and edit values:

```bash
copy .env.example .env
```

On Linux/macOS: `cp .env.example .env`

Set at least:

- `JWT_SECRET` — long random string (used to sign tokens).
- `ALGORITHM` — e.g. `HS256` (must match what the app expects).

### 6. Run the API with Uvicorn

From the **project root** (where `main.py` lives), with `venv` activated:

```bash
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Defaults without flags: host `127.0.0.1`, port `8000`.

Alternative (uses `uvicorn.run` inside `main.py`):

```bash
python main.py
```

## API documentation and testing

After the server starts:

| URL | Purpose |
|-----|---------|
| [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) | **Swagger UI** — try endpoints, schemas, and **Authorize** |
| [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc) | **ReDoc** — readable reference |
| [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json) | OpenAPI schema (for Postman/Insomnia import) |

### Testing with Swagger UI

1. Open `/docs`.
2. Call **POST** `/Login` with `email` and `password`.
3. Copy `access_token` from the response `data` object (wrapped in your standard success payload).
4. Click **Authorize**, enter: `Bearer <paste_token>` (include the word `Bearer` and a space before the token).
5. Call protected endpoints (e.g. user or record APIs).

## API route map

Routers are mounted **without** a path prefix; paths below are the full path (case-sensitive as defined in code).

### User (`user` tag)

| Method | Path | Notes |
|--------|------|--------|
| POST | `/Login` | Public; returns JWT |
| POST | `/Create-User` | Admin only |
| GET | `/Get-Users` | Admin only |
| GET | `/Get_Users_By_Id` | Query: `user_id`; admin only |
| PATCH | `/User_Update/{user_id}` | Admin only |
| PATCH | `/User-Status-Update/{user_id}` | Body: active flag; admin only |
| PATCH | `/User/Block-Unblock/{user_id}` | Body: `is_blocked`; admin only |
| DELETE | `/Delete-User/{user_id}` | Admin only |

### Financial records (`financial_records` tag)

| Method | Path | Notes |
|--------|------|--------|
| POST | `/Create-Record` | Admin only |
| GET | `/Get-AllRecords` | Analyst or admin (not viewer) |
| GET | `/Get-Record-By-ID/{record_id}` | Analyst or admin |
| PATCH | `/Update-Record/{record_id}` | Admin only |
| DELETE | `/Delete-Record/{record_id}` | Admin only |
| GET | `/Filter_Records` | Query: `type`, `category`, `start_date`, `end_date`; analyst or admin |

### Dashboard (`dashboard-summary` tag)

| Method | Path | Notes |
|--------|------|--------|
| GET | `/Dashboard-Summary` | Authenticated |
| GET | `/Category-Summary` | Authenticated |
| GET | `/Recent-Activity` | Authenticated |
| GET | `/monthly-trends` | Authenticated |
| GET | `/Weekly-Trends` | Authenticated |

Exact role checks are implemented in each handler; use `/docs` to see request/response models.

## Project layout (main pieces)

- `main.py` — FastAPI app, CORS, router includes, DB table creation.
- `app/user/` — user routes, models, schemas, login.
- `app/financial_records/` — records CRUD and filters.
- `app/dashboard/` — aggregates and trends.
- `shared/db.py` — SQLite URL and session.
- `common/` — JWT, password hashing, and **`successResponse` / `errorResponse`** for a single API response contract.
